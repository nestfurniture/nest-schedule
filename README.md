# 네스트퍼니처

네스트퍼니처 통합관리 웹앱입니다. 현장별 실측일, 시공 기간과 날짜별 시공자 배정, 마감 추가 투입 인원과 AS를 관리하고, 현장마다 사진·도면·견적서를 보관합니다.
시공자별 일정판(겹침 경고), 견적서 작성(고객 링크·PDF), 수금 관리, 결산(연·월·현장별 매출·매입·지출)과 시공자 정산(관리자만), 휴대폰 알림(아침·저녁 일정)도 들어 있습니다.
PC와 휴대폰 브라우저에서 쓰고, 휴대폰 홈 화면에 설치하면 앱처럼 전체 화면으로 열립니다.

## 메뉴

화면은 큰 메뉴 다섯 개로 묶여 있고, 그 안에 세부 화면이 있습니다. PC와 휴대폰 모두 큰 메뉴는 맨 위 글자 메뉴(고른 메뉴에 주황 밑줄), 세부 화면은 그 아래 작은 글자 탭이고, 그 밑에 지금 화면 이름이 명조체 제목으로 나옵니다. 관리자가 아닌 계정은 **오늘**과 **현장**만 봅니다.

| 메뉴 | 세부 화면 |
| --- | --- |
| 오늘 | 오늘 할 일 (앱을 열면 처음 보이는 화면) |
| 현장 | 현장 목록 (+ 현장 추가, 검색, 분류 단추) · 진행 흐름 · 달력 · 시공자별 |
| 견적 | 견적서 (+ 새 견적서, 회사 정보 · 단가표) |
| 정산 | 고객 수금 · 시공자 정산 |
| 결산 | 손익 (연·월·현장별 매출·매입·지출·순이익) · 회사 지출 (지출 적기·고치기) |

메뉴마다 마지막에 본 세부 화면을 기억합니다. 휴대폰에서는 **+ 현장 추가** / **+ 새 견적서**가 오른쪽 아래에 떠 있는 단추로 나오고, 글자를 입력하는 동안이나 현장 수정 화면이 열려 있을 때는 잠시 숨습니다. 급한 일 개수는 **오늘** 옆에 작은 빨간 숫자로 붙습니다.

### 오늘 할 일

앱을 처음 켜면 먼저 보이는 화면입니다. 쓰는 중에 잠깐 다른 앱으로 나갔다 오면 보던 화면과 입력하던 내용이 그대로 있습니다. 이름을 누르면 현장 내용이, 날짜를 누르면 그날 일정이 열립니다.

- **숫자 칸**: 진행중인 현장, 7일 안에 시공하는 현장, (관리자) 미수금과 이번 달 들어온 돈. 누르면 해당 화면으로 갑니다.
- **오늘 일정 · 내일 일정**: 시공(그날 들어가는 시공자, 며칠째), 실측, AS, 마감 추가 투입.
- **앞으로 7일**: 모레부터 7일 동안 일정이 있는 날만 한 줄씩.
- **확인할 일**: 할 일이 있는 것만 보입니다. 빨간 것은 급한 일이고, 그 개수가 메뉴의 **오늘**에 숫자로 붙습니다.
  - 빨강: 7일 안에 시공자 미배정, 시공자 겹침(60일 안), 입금 지연(관리자), 체크리스트 문제 미조치, AS 날짜 지남, 납기 지났는데 생산 완료 체크 안 함, 7일 안에 시공인데 생산 완료 전, 납기가 시공 시작보다 늦음
  - 노랑: 도면 확정 목표일 지남, 체크리스트 미제출, 실측 완료 체크 안 함, 시공 끝났는데 마감 완료 전, 보낸 지 2일 넘었는데 고객이 안 연 견적서(관리자), 지난달 시공자 정산 지급 전(관리자, 일당을 넣은 경우)
  - 회색: 실측일·시공일이 둘 다 없는 현장

### 진행 흐름 (도면 확정 · 생산 · 납기)

현장 › **진행 흐름**에서 현장마다 지금 어느 단계인지 봅니다. **달력에는 나오지 않고** 이 화면, 현장 보기, 오늘 할 일에만 나옵니다.

- **단계**: 문의 › 실측 › 설계·견적 › 도면 확정 › 생산 › 시공 대기 › 시공 › 정산(관리자) › 완료. 위 단추를 누르면 그 단계 현장만 보이고, 완료된 현장은 **완료**를 눌러야 보입니다. 늦어진 현장은 각 단계 맨 위에 빨갛게 나옵니다.
- **단계 정하는 법**: 실측일이 있으면 실측, 실측 완료면 설계·견적, 계약(계약금액이 있거나 시공일이 잡힘)이면 도면 확정, 도면 확정 체크하면 생산, 생산 완료 체크하면 시공 대기, 시공이 시작되면 시공, 마감 완료면 정산(정산 종료 전, 관리자만 보임) 또는 완료입니다.
- **수정 › 도면 · 생산**: 설계 담당(대표, 외주 디자이너, 설계 직원 등 이름을 적으면 다음부터 고를 수 있음), 도면 확정 목표일, 도면 확정 체크, 생산 방식(자체 공장 / 외주 / 자체 + 외주, 외주면 외주처), 납기(생산 완료 예정일), 생산 완료 체크. 납기가 시공 시작보다 늦으면 바로 경고가 뜹니다.
- **현장 보기**: **진행 단계** 줄(실측 · 계약 · 도면 확정 · 생산 · 시공 · 마감, 관리자는 정산까지)이 보이고, **바로 체크**에 지금 단계의 **도면 확정** / **생산 완료**가 나옵니다. 예전 현장처럼 기록 없이 지나간 단계는 "기록 없음"으로 보입니다.
- 계약일은 수금의 계약일을 따라가서 직원 계정에서도 계약 여부가 보입니다(돈은 안 보임). 시공자 체크리스트 화면에는 나가지 않습니다. 엑셀 백업 현장 시트에 진행 단계, 계약일, 설계 담당, 도면 확정 목표·확정일, 생산, 외주처, 납기, 생산 완료일이 들어갑니다.

### 이름 표시

화면 위에는 로그인 계정(이메일) 대신 **ㅇㅇㅇ님**이 보입니다. 처음에는 **이름 넣기**가 보이고, 누르면 이름을 적을 수 있습니다(나중에 눌러서 바꿀 수도 있음). 이름은 로그인 계정에 저장돼서 다른 기기에서 로그인해도 같습니다. 같은 창(**내 정보**)에서 지금 계정이 관리자인지 직원인지도 알려 주고, 맨 아래 **로그아웃**도 여기 있습니다. 이름 옆 종 모양 단추가 휴대폰 알림 설정입니다. 돈 관련 내용(미수금, 들어온 돈, 수금·매입, 정산, 결산, 견적서)은 관리자 계정에만 보이므로, 직원은 각자 직원 계정으로 로그인해야 합니다.

### 빠른 등록 · 고객 전화번호 · 검색

- **빠른 등록**: 현장 › **+ 현장 추가**를 누르면 고객명, 전화번호, 현장 주소, 실측일만 적는 작은 창이 뜹니다. 저장하면 바로 현장이 만들어지고 그 현장 보기가 열립니다. 같은 전화번호로 등록된 현장이 있으면 알려 줍니다(다시 찾은 고객). 품목·시공일·시공자 같은 나머지는 나중에 **수정**에서 넣거나, 처음부터 다 적으려면 **자세히 입력**을 누릅니다(적은 내용이 그대로 넘어감).
- **고객 전화번호**: 현장마다 고객 전화번호 칸이 있습니다. 숫자만 적어도 `010-1234-5678`처럼 맞춰지고, 현장 보기에서 **전화**·**문자**를 누르면 휴대폰에서 바로 걸거나 보낼 수 있습니다. 견적서를 현장에서 만들면 연락처가 채워지고, 연결 안 된 견적서를 계약으로 확정해 새 현장이 생기면 견적서의 연락처가 현장에 들어갑니다. 엑셀 백업 현장 시트에도 들어갑니다. 시공자 체크리스트 화면에는 나가지 않습니다.
- **현장 검색**: 현장 목록 위 검색칸에 이름, 품목, 주소, 전화번호(숫자 일부만 적어도 됨), 시공자, 현장 담당자를 적으면 맞는 현장만 보입니다. 검색할 때는 종료 현장도 같이 찾고, 분류 단추를 누른 상태면 그 안에서만 찾습니다.

### 정산 보기 (관리자)

정산(고객 수금 · 시공자 정산)이나 결산(손익)에서 현장을 누르면 돈에 관한 것만 보입니다. 시공자 문자, 현장 출입, 가전·체크리스트 같은 현장 내용은 빠지고, 아래만 나옵니다. 현장 화면에서 누르면 예전처럼 현장 보기가 열리고, 두 화면은 **정산 보기** / **현장 내용 보기** 단추로 오갈 수 있습니다.

- **수금**: 계약금액, 받은 돈, 입금 일정마다 **입금 확인** 체크. 남은 입금이 두 건 이상이면 **수금 완료**(남은 것 모두 입금 확인) 체크가 하나 더 있습니다. 잘못 눌렀으면 창을 닫기 전에 **되돌리기**.
- **매입**: 적힌 매입과 일당으로 자동 계산한 인건비. **매입 입력**(또는 **+ 매입 추가**)을 누르면 항목·금액·메모를 그 자리에서 넣을 수 있습니다.
- **이익**: 매출(계약금액) − 매입.
- **견적서**: 이 현장의 견적서와 **+ 견적서 작성**.
- **정산 종료**: 받을 돈 다 받음 · 매입 입력, 두 가지가 되면 **정산 종료**로 넘어갑니다. **수금 완료를 해도 매입이 입력되어 있지 않으면 넘어가지 않고**, 매입 칸이 빨갛게 "매입 입력 안 됨"으로 뜹니다(고객 수금 목록과 오늘 할 일의 확인할 일에도 빨갛게 뜸). 일당으로 자동 계산한 인건비만 있는 것은 매입 입력으로 치지 않습니다.

**현장 종료와 정산 종료는 따로입니다.** 현장 쪽은 시공 기준이라 **시공 마감 완료**를 체크하면 미수금이 남아 있어도 **종료 현장**으로 넘어갑니다. 정산 쪽은 수금·매입 기준이라 고객 수금의 **현장별 수금**이 **정산 중** / **정산 종료**로 나뉘고, 수금이 덜 됐거나 매입이 없으면 정산 중에 남습니다. 정산이 끝나도 현장은 마감 완료 체크 전까지 진행중으로 남습니다.

### 입금 받을 날 자동

입금 일정의 **받을 날**을 비워 두면 자동으로 들어갑니다: **계약금 = 계약일, 중도금 = 시공 시작일, 잔금 = 시공 끝나는 날**(쉬는 날·주말 빼고 마지막 작업일). 시공일이 아직 없으면 정해지는 대로 채워지고, 나중에 시공일이 바뀌면(직원이 바꿔도) 관리자 앱이 열릴 때 따라 바뀝니다. 받을 날을 직접 고친 입금, 이미 입금된 것, 추가금, 종료 현장은 건드리지 않습니다. 견적서를 계약으로 확정할 때 만들어지는 입금 일정도 같습니다. 그래서 입금 지연(확인할 일, 아침 알림)이 받을 날이 비어 있던 계약에도 뜹니다.

### 바로 체크 (현장 보기)

현장을 누르면 나오는 보기 화면 맨 위 **바로 체크**에서 **수정**에 들어가지 않고 체크할 수 있습니다. 체크하면 바로 저장되고 그 칸은 사라집니다. 잘못 눌렀으면 그 화면을 닫기 전까지 **되돌리기**를 누르면 됩니다.

- **실측 완료**: 실측일이 비어 있으면 오늘 날짜로 적힙니다.
- **도면 확정** / **생산 완료**: 그 단계에 있는 현장만 보입니다. 체크하면 오늘 날짜로 적힙니다.
- **입금 확인** (관리자): 입금 일정마다 하나씩. 체크하면 오늘 날짜로 입금됨이 됩니다. 일부만 들어온 경우처럼 금액을 바꿔야 하면 **수정**에서 고칩니다.
- **시공 마감 완료**: 시공을 시작한 현장만 보입니다.
- **AS 완료**: 끝나지 않은 AS마다 하나씩.

- 화면: `index.html`, `app.js`, 견적서 문서 `estimate.js`, 고객용 견적서 `est.html` (빌드 과정 없음, 파일 그대로 올리면 됨)
- 저장·로그인·파일 보관: Supabase (`supabase/schema.sql` + `update-02.sql` + `update-03.sql`, 비공개 Storage 버킷 `job-files`)
- 알림 보내기: Supabase Edge Function `notify` (`supabase/functions/notify/index.ts`)
- 설치(PWA): `manifest.webmanifest`, `sw.js`, `icons/`

## 처음 설정

1. Supabase 프로젝트를 만들고 SQL Editor에서 `supabase/schema.sql`, 이어서 `supabase/update-02.sql` 내용을 실행합니다. 표(jobs, crew, files, admins, job_money)와 파일 보관함(job-files)이 만들어집니다.
2. Authentication → Sign In / Providers에서 "Allow new users to sign up"을 끕니다. (아무나 가입하지 못하게)
3. Authentication → Users → Add user로 사장님과 직원 계정(이메일, 비밀번호)을 만듭니다. "Auto Confirm User"를 체크하세요.
4. `config.js`에 Project URL과 anon public 키를 넣습니다. service_role 키는 넣지 않습니다.
5. GitHub 저장소 Settings → Pages에서 Source를 "Deploy from a branch", 브랜치 `main`, 폴더 `/ (root)`로 저장합니다.
   잠시 뒤 `https://<계정>.github.io/nest-schedule/` 주소로 열립니다.

## 업데이트 2 (현장 사진 · 수금 · 매출) 적용

이미 쓰고 있는 앱에는 Supabase → SQL Editor → New query에 `supabase/update-02.sql` 내용을 통째로 붙여넣고 Run을 한 번 누르면 됩니다.
처음 실행할 때 가장 먼저 만든 계정(사장님)이 관리자로 등록되고, 관리자만 계약금액·입금·원가·매출 화면을 볼 수 있습니다.

다른 계정도 관리자로 만들려면 SQL Editor에서 이메일만 바꿔 실행하세요.

```sql
insert into public.admins (user_id, email)
select id, email from auth.users where email = '직원이메일@example.com'
on conflict do nothing;
```

## 업데이트 3 (휴대폰 알림) 적용

매일 저녁 6시에 내일 일정, 아침 7시 30분에 오늘 일정과 시공자 미배정 현장을 휴대폰 알림으로 보냅니다. 관리자에게는 아침에 오늘 받을 돈과 입금 지연도 함께 갑니다.
앱을 닫아 둬도 옵니다. 알림을 누르면 앱이 열리면서 그날 일정(또는 수금 화면)이 바로 보입니다.

1. **알림 서버 만들기 (한 번만)**: Supabase → 왼쪽 **Edge Functions** → **Deploy a new function** → **Via Editor**.
   이름 칸에 정확히 `notify` 라고 적고, 편집기 내용을 지운 뒤 [`supabase/functions/notify/index.ts`](supabase/functions/notify/index.ts) 내용을 통째로 붙여넣고 **Deploy function**.
   비밀 키를 따로 넣을 필요는 없습니다(서버 안에 원래 들어 있는 값을 씁니다).
2. **SQL 실행 (한 번만)**: SQL Editor → New query에 `supabase/update-03.sql` 내용을 통째로 붙여넣고 Run.
   맨 아래에 `nest-push-morning`, `nest-push-evening` 두 줄이 보이면 끝입니다.
3. **기기마다 켜기**: 앱 오른쪽 위 종 모양 **알림** 단추 → **이 기기에서 알림 켜기** → 허용 → **테스트 알림 보내기**.
   - 아이폰은 Safari에서 "홈 화면에 추가"한 앱으로 열어야 켤 수 있습니다(iOS 16.4 이상).
   - 기기마다 받을 알림(내일 일정 / 오늘 일정 / 입금)을 고를 수 있고, 로그아웃하면 그 기기 알림은 꺼집니다.

알림 시간을 바꾸려면 `update-03.sql`의 `30 22 * * *`(아침), `0 9 * * *`(저녁)을 고쳐 다시 실행하면 됩니다. 시간은 세계 표준시라 한국 시간에서 9시간을 빼서 적습니다. 아침 알림은 한국 시간 새벽 5시~낮 12시, 저녁 알림은 오후 3시~밤 11시 사이로만 정할 수 있습니다.

## 업데이트 4 (시공 체크리스트 · 가전 시방서) 적용

시공자가 시공을 마치고 휴대폰으로 체크리스트를 작성합니다. 가전마다 시방서 치수와 실제로 잰 치수, 시방서대로 설치했는지(통풍 간격, 도어 패널, 급배수, 전원 등)를 확인하고 사진을 남깁니다. 시공자는 로그인 없이 문자로 받은 링크로만 들어옵니다.

1. **SQL 실행 (한 번만)**: SQL Editor → New query에 `supabase/update-04.sql` 내용을 통째로 붙여넣고 Run. 맨 아래에 `체크리스트 준비 완료`가 보이면 끝입니다.
2. **알림 서버 고치기 (한 번만)**: Supabase → Edge Functions → `notify` → **Code** 탭에서 내용을 모두 지우고 [`supabase/functions/notify/index.ts`](supabase/functions/notify/index.ts) 새 내용을 통째로 붙여넣은 뒤 **Deploy**. 시공자 화면은 이 서버를 거쳐서만 저장됩니다.

쓰는 법
- 현장 수정 화면 **가전 · 시방서** 칸에 빌트인 가전 모델명만 적습니다. 업데이트 5를 하면 시방서는 모델명으로 자동으로 찾아 붙습니다. 공식 자료가 없는 가전은 **파일 직접 올리기**로 이 현장에만 올릴 수 있습니다.
- 같은 화면 **시공 체크리스트** 칸에서 **체크리스트 링크 만들기** → **체크리스트 문자 복사**해서 시공자에게 보냅니다. 달력에서 날짜를 눌러도 **체크리스트 문자 복사**가 있습니다.
- 시공자가 제출하면 알림이 오고(알림 설정의 "시공 체크리스트 제출"), 결과와 사진이 현장 화면에 보입니다. 문제로 적은 항목이 있으면 현장 목록에 빨갛게 표시되고, 고친 뒤 **문제 조치 완료**를 체크하면 사라집니다.
- 고칠 게 있어 다시 작성해야 하면 **다시 작성하게 열기**를 누르면 같은 링크로 다시 들어갈 수 있습니다.
- 시공이 끝났는데 체크리스트가 안 온 현장은 끝난 다음 날부터 7일 동안 아침 알림에 함께 나옵니다.
- 확인 항목 문구는 `checklist.js` 한 곳에서 고칩니다. 현장마다 따로 확인할 것은 **이 현장 추가 확인** 칸에 한 줄에 하나씩 적습니다.

## 업데이트 5 (시방서 자동 찾기) 적용

가전 모델명을 적고 저장하면, 알림 서버(`notify`)가 Claude(Anthropic의 AI)를 시켜 그 모델의 설치 시방서를 찾아 붙입니다. 제조사 공식 홈페이지를 먼저 찾고, 없으면 다른 출처에서 찾습니다(업데이트 6). 찾은 시방서는 모델별 보관함(`app_specs`)에 남아서, 같은 모델은 다음 현장부터 다시 찾지 않고 바로 붙습니다.

1. **Anthropic API 키 만들기 (한 번만)**: https://platform.claude.com 에 가입 → **Billing**에서 크레딧 충전(처음엔 5달러면 충분) → **API Keys** → **Create Key**. 키는 `sk-ant-`로 시작하고 만들 때 한 번만 보입니다. **Limits**에서 한 달 사용 한도(예: 20달러)를 정해 두면 그 이상은 쓰이지 않습니다.
2. **키 넣기 (한 번만)**: Supabase → **Edge Functions** → **Secrets** → 이름 `ANTHROPIC_API_KEY`, 값에 키를 붙여넣고 **Save**. 키는 여기에만 넣고 채팅·문자·앱 어디에도 보내지 마세요.
3. **SQL 실행 (한 번만)**: SQL Editor → New query에 [`supabase/update-05.sql`](supabase/update-05.sql) 내용을 통째로 붙여넣고 Run. 맨 아래에 `시방서 보관함 준비 완료`가 보이면 끝입니다.
4. **알림 서버 고치기 (한 번만)**: Supabase → Edge Functions → `notify` → **Code** 탭에서 내용을 모두 지우고 [`supabase/functions/notify/index.ts`](supabase/functions/notify/index.ts) 새 내용을 통째로 붙여넣은 뒤 **Deploy**.

쓰는 법
- 도면을 보고 **가전 · 시방서** 칸에 모델명만 적고 저장합니다. 몇 분 뒤 가전 줄 아래에 종류, 시공 때 맞춰야 할 치수, 치수도, 설명서·링크, 찾은 곳(출처)이 붙습니다. 앱을 닫아도 서버에서 계속 찾습니다. 저장하기 전에 **지금 찾기**를 눌러도 됩니다.
- 종류는 "종류 자동"으로 두면 찾은 시방서의 종류로 정해집니다.
- 어디에서도 못 찾으면 "어디에서도 찾지 못했어요"가 뜹니다. 모델명을 확인하고 **다시 찾기**를 누르세요. 그래도 없으면 **파일 직접 올리기**로 이 현장에만 올릴 수 있습니다.
- 어떤 현장만 치수가 다르면 "이 현장만 다른 치수" 칸에 적으면 그 현장에서는 그 값이 먼저 보입니다.
- 찾은 시방서는 같은 모델을 쓰는 모든 현장의 시공 체크리스트에 자동으로 붙습니다. PDF 설명서는 보관함에 복사해 두어서 제조사 주소가 바뀌어도 열립니다.

## 업데이트 6 (다른 출처 · 냉장고 붙여서 설치) 적용

- **공식 홈페이지에 없으면 다른 출처에서**: 제조사 공식 홈페이지(국내 → 해외)에 없으면 판매처 상품정보(롯데하이마트, 전자랜드, 다나와 등), 설명서 모음 사이트, 같은 시리즈 모델 순서로 찾습니다. 공식 자료가 아니면 앱과 시공자 화면에 **공식 자료 아님 · 출처: ○○**와 "현장에서 실측으로 꼭 확인해 주세요"가 함께 나옵니다.
- **더 끈질기게**: 한 번에 다 못 찾으면 서버가 이어서 몇 차례 더 찾습니다. 그래서 새 모델은 몇 분 걸릴 수 있습니다.
- **냉장고 붙여서 설치**: 한 현장에 냉장고·김치냉장고·와인셀러가 2대 이상이면 "옆 냉장고·김치냉장고와 붙여서 설치"가 기본으로 체크되고, 그 조합 그대로 설치할 때의 연결 시방서(묶음 전체 설치 공간, 제품 사이 간격·연결 키트, 통풍 간격)를 따로 찾습니다. 각 가전을 다 찾은 뒤에 자동으로 찾습니다. 시공 체크리스트에는 **붙여서 설치** 칸(5가지 확인 + 실측 + 사진)이 생깁니다. 따로 떨어져 설치하는 가전은 체크를 끄면 묶음에서 빠집니다.
- 예전 방식으로 못 찾았던 모델은 앱을 처음 열 때 새 방식으로 한 번 다시 찾습니다.

1. **SQL 실행 (한 번만)**: SQL Editor → New query에 [`supabase/update-06.sql`](supabase/update-06.sql) 내용을 통째로 붙여넣고 Run. 맨 아래에 `시방서 출처 칸 준비 완료`가 보이면 끝입니다.
2. **알림 서버 고치기 (한 번만)**: Supabase → Edge Functions → `notify` → **Code** 탭에서 내용을 모두 지우고 [`supabase/functions/notify/index.ts`](supabase/functions/notify/index.ts) 새 내용을 통째로 붙여넣은 뒤 **Deploy**.
3. 확인은 GitHub **Actions** → **알림 서버 점검** → **Run workflow**. 7번에 `"v":2`(업데이트 7까지 했으면 `"v":3`), 8번에 `[]`, 9번에 `403`이 보이면 됩니다.

## 업데이트 7 (시방서를 그림으로) 적용

시방서를 글자 대신 **치수도 그림**으로 크게 보여 줍니다. 앱의 가전 줄 아래와 시공자 체크리스트 화면 모두 그림이 먼저 나오고, 글자 요약과 원본 링크는 **글자·원본 자료 보기**를 누르면 펼쳐집니다.

- 찾을 때 나온 치수도 그림과 제조사가 정해 둔 그림(LG 제품 치수 그림, LG 냉장고 설치가이드·2대 연결 그림 등)을 받아 와서, Claude가 그림을 직접 보고 설치 치수도만 골라 제목을 붙입니다. 광고 사진·빈 그림·다른 모델 그림은 뺍니다.
- 고른 그림은 보관함(`job-files/lib/spec/`)에 복사해 두어서 제조사 주소가 바뀌어도 계속 보입니다.
- 설명서 PDF만 있는 모델(삼성 등)은 사무실 앱이 열려 있을 때 PDF에서 치수 쪽을 찾아 그림으로 캡처해 둡니다. 한 번 캡처하면 모든 현장과 시공자 화면에 같이 나옵니다.
- 전에 찾아 둔 시방서도 앱을 열면 그림으로 정리합니다(다시 찾지는 않아서 찾기 비용은 들지 않음).

1. **알림 서버 고치기 (한 번만)**: Supabase → Edge Functions → `notify` → **Code** 탭에서 내용을 모두 지우고 [`supabase/functions/notify/index.ts`](supabase/functions/notify/index.ts) 새 내용을 통째로 붙여넣은 뒤 **Deploy**. SQL은 하지 않아도 됩니다.
2. 확인: **알림 서버 점검**에서 7번에 `"v":3`, 10번에 `403`이 보이면 됩니다.

비용: 그림 고르기는 가벼운 모델(Claude Haiku)로 해서 모델 하나에 몇 원~수십 원 정도입니다. 바꾸려면 Secrets에 `SPEC_VISION_MODEL`을 넣습니다.

비용
- 새 모델 하나를 찾을 때 보통 몇백 원에서 2천 원 정도 듭니다(Claude 사용료와 웹 검색 몇 번, 모델마다 다름). 공식 홈페이지에 없어 여러 차례 찾는 모델이나 붙여서 설치 묶음은 몇천 원, 드물게 1만 원 가까이 들 수 있습니다. 같은 모델·같은 묶음은 다시 찾지 않아서 0원입니다.
- 실수로 많이 찾지 않도록 24시간에 30개까지만 찾습니다. 바꾸려면 Secrets에 `SPEC_DAY_CAP`(숫자)을 넣습니다.
- 키를 넣지 않으면 자동 찾기만 꺼지고 앱의 나머지는 그대로 동작합니다.
- 크레딧이 떨어지면 가전 줄 아래에 "Claude API 크레딧이 모자라요"가 뜹니다. Claude Console(platform.claude.com) → Billing에서 충전하고 **다시 찾기**를 누르세요.

## 업데이트 8 (시공자 정산) 적용

관리자 계정에 **정산 › 시공자 정산** 화면이 생깁니다. 시공자마다 일당을 한 번 넣어 두면, 현장 일정(시공 기간 + 배정된 시공자)으로 달마다 줄 돈이 자동으로 계산됩니다.

- **시공일 세는 법**: 시공 기간 중 평일(토·일은 그 현장에 체크한 날만). 한 사람이 같은 날 두 현장에 잡혀 있으면 하루로 셉니다. AS는 담당으로 적힌 사람의 하루로 셉니다(AS 하루 금액을 따로 넣을 수 있고, 비우면 각자 일당). 마감 추가 투입은 이름 없이 인원만 적혀 있어서 "마감 추가 투입 1인" 금액 × 인원으로 따로 셉니다.
- **조정**: 반일·유류비·식대처럼 일정으로 셀 수 없는 금액은 시공자 카드의 **조정 금액**에 적습니다(빼는 금액은 `-125,000`처럼 앞에 `-`).
- **지급 완료**: 체크하면 그날 날짜와 그때 금액이 남습니다. 나중에 일정이 바뀌면 금액은 그대로 두고 "지금 계산하면 ○원"이라고 알려 줍니다.
- **정산 문자 복사**: 현장별 날짜와 합계가 들어간 문자를 복사해 시공자에게 보낼 수 있습니다.
- **원가에 자동 반영**: 일당을 넣으면 결산의 현장 매입 중 **시공 인건비**와 **추가 투입 인건비**가 일정 기준으로 자동으로 채워집니다. 그 현장에 같은 항목을 직접 적었으면 직접 적은 금액만 씁니다(두 번 더하지 않음).
- 시공자가 정해지지 않은 시공일은 정산에 들어가지 않고 아래에 따로 표시됩니다.

1. **SQL 실행 (한 번만)**: 업데이트 9나 10을 할 거면 건너뛰어도 됩니다(둘 다 8이 들어 있음). SQL Editor → New query에 [`supabase/update-08.sql`](supabase/update-08.sql) 내용을 통째로 붙여넣고 Run. 맨 아래에 `시공자 정산 표 준비 완료`가 보이면 끝입니다. 알림 서버는 고치지 않아도 됩니다.
2. 확인: **알림 서버 점검**에서 11번에 `[]`이 보이면 됩니다.

## 업데이트 9 (결산 · 날짜별 시공자 · 현장 분류) 적용

- **결산 › 손익** (예전 매출·원가 탭): 연도별·월별·현장별로 **매출 − 매입 − 지출 = 순이익**을 보여 줍니다. 현장의 매출·매입은 **시공을 시작한 달**에 들어갑니다(10월 30일에 시작해 11월에 끝나도 10월 매출). 시공일이 없으면 계약일의 달입니다. 매출은 계약금액, 매입은 현장 원가(현장 화면의 **수금 · 매입**에 적은 자재·외주 등 + 일당으로 자동 계산한 인건비), 지출은 현장에 딸리지 않은 회사 비용입니다. 실제로 들어온 돈(입금)도 함께 보여 줍니다.
- **회사 지출 기록**: 결산 › 회사 지출에서 날짜·항목(임대료, 차량·유류, 공구·장비 …)·금액을 적습니다. 임대료처럼 매달 나가는 돈은 **매달 나가는 돈**에 체크하면 시작한 달부터 이번 달까지 매달 들어갑니다(끝나는 달을 넣으면 거기까지). 적은 줄을 누르면 고치거나 지울 수 있습니다.
- **날짜별 시공자**: 현장 수정 화면의 시공자 아래 **날짜별로 시공자 다르게 정하기**를 펼치면 날마다 들어가는 사람을 따로 고를 수 있고, 작업이 없는 날은 **쉬는 날**로 뺄 수 있습니다. 달력, 시공자별 일정판, 겹침 경고, 시공자 정산, 휴대폰 알림, 시공자 문자 모두 날짜별 시공자로 계산합니다.
- **현장 보기**: 현장 목록에서 현장을 누르면 내용만 먼저 보여 주고, **수정**을 눌러야 입력 화면이 열립니다(휴대폰 키패드가 바로 뜨지 않음).
- **현장 분류**: 위쪽 칸이 대기중인 현장(시공 전) / 진행중인 현장(시공 시작 후) / 종료 현장 / AS / 시공자 미배정 / 시공자 겹침으로 바뀌었고, 누르면 그 현장만 목록에 보입니다(다시 누르면 전체). **시공 마감 완료**를 체크한 현장은 **종료 현장**으로 옮겨집니다(수금·매입은 정산에서 따로 마무리, 위 **정산 보기** 참고). 취소된 현장처럼 마감 없이 끝낼 때는 현장 보기에서 **지금 종료 처리**, 되돌릴 때는 **다시 진행중으로**(마감 완료 체크도 풀림). 기본 목록에는 종료 현장이 빠집니다.

1. **SQL 실행 (한 번만)**: 업데이트 10을 할 거면 건너뛰어도 됩니다(10에 들어 있음). SQL Editor → New query에 [`supabase/update-09.sql`](supabase/update-09.sql) 내용을 통째로 붙여넣고 Run. 맨 아래에 `시공자 정산 · 결산 표 준비 완료`가 보이면 끝입니다. 업데이트 8을 아직 안 했어도 이것 하나로 같이 됩니다.
2. **알림 서버 고치기 (한 번만)**: Supabase → Edge Functions → `notify` → **Code** 탭에서 내용을 모두 지우고 [`supabase/functions/notify/index.ts`](supabase/functions/notify/index.ts) 새 내용을 통째로 붙여넣은 뒤 **Deploy**. 휴대폰 알림이 날짜별 시공자와 쉬는 날을 알게 됩니다.
3. 확인: **알림 서버 점검**에서 11번과 12번에 `[]`이 보이면 됩니다.

## 업데이트 10 (견적서 작성) 적용

관리자 계정에 **견적** 메뉴가 생깁니다. 견적서를 앱에서 쓰고, 고객에게 링크로 보내고, 계약이 되면 버튼 하나로 수금·결산에 넣습니다.

- **견적서 모양**: 회사 엑셀 견적서(`네스트퍼니처_견적서.xlsx`)와 같은 모양입니다. **표지**(프로젝트·업체·현장·담당·견적일·견적번호·유효기간·총 견적금액) → **요약**(공간별 금액과 비중, 공급가 합계·특별 할인·단수 조정·공급가액·부가세, 결제 일정, 입금 계좌, 서명란) → **공간별 상세 견적**(품목·규격·소재·마감·하드웨어·수량·단위·단가·금액·비고, 공간마다 소계, 인쇄하면 공간마다 새 장) → **사양 및 조건**. 견적번호는 `NF-견적일`(같은 날 두 번째부터 `-2`), 부가세는 엑셀처럼 원 단위 미만을 버립니다.
- **처음 한 번**: 견적 화면 아래 **회사 정보 · 도장**에 상호·영문 브랜드명·브랜드 문구·대표자·사업자등록번호·주소·전화·이메일·웹사이트/SNS·입금 계좌를 넣고 도장 사진을 올립니다(흰 종이에 찍은 도장 사진이면 흰 바탕은 비쳐 보입니다). 새 견적서에 처음 들어갈 유효기간(기본 15일), 견적번호 앞글자(기본 NF), 결제 일정(계약금 30% 계약 체결 시 · 중도금 40% 제작 착수 전 · 잔금 30% 설치 완료 및 검수 후), **사양 및 조건** 문구도 여기서 정합니다. 사양 및 조건은 `[제목]` 줄이 묶음 제목, `항목: 내용` 줄이 표 한 줄이 됩니다.
- **단가표**: **자주 쓰는 품목**에 품목·규격·소재·마감·하드웨어·단위·단가를 넣어 두면 견적서에서 품목을 고를 때 나머지가 채워집니다. 견적서 품목 옆 ☆을 눌러도 단가표에 들어갑니다.
- **견적서 쓰기**: **+ 새 견적서**(또는 현장 보기의 **+ 견적서 작성**) → 프로젝트·업체·담당·현장 → **+ 공간**으로 현관·주방·안방 등을 고르면 영문 이름과 주요 구성이 채워짐 → 공간 아래 품목(금액은 자동) → 특별 할인·단수 조정(빼기/더하기)·부가세 → 결제 일정 → 사양 및 조건. 연락처는 문자 보낼 때만 쓰고 견적서에는 안 나옵니다.
- **미리보기 · PDF**: **미리보기**에서 견적서를 보고 **인쇄 · PDF 저장**으로 A4 PDF를 받습니다(컴퓨터는 인쇄 창에서 'PDF로 저장', 휴대폰은 인쇄 화면의 공유 버튼).
- **고객에게 보내기**: **고객에게 보낼 문자 복사**를 누르면 링크가 든 문자가 복사돼서 문자·카톡에 붙여넣으면 됩니다. 고객은 로그인 없이 휴대폰으로 견적서를 보고, 인쇄·PDF 저장과 전화하기를 누를 수 있습니다. 고객이 열어 보면 목록의 **고객 확인**에 횟수와 시간이 나옵니다(회사 앱에 로그인된 기기에서 연 것은 세지 않음).
- **계약으로 확정**: 연결된 현장(없으면 새로 만듦)에 계약금액과 결제 조건대로 나눈 입금 일정이 들어가서 수금·결산에 바로 잡힙니다. 이미 입금 일정이 적혀 있으면 그대로 둡니다. 받을 날은 현장 수정 화면의 수금에서 정하면 됩니다.
- **2차 · 3차 견적**: **새 버전으로 복사**를 누르면 같은 견적번호로 2차가 만들어집니다. 안 된 견적은 **안 됨으로 표시**해 둡니다.
- 견적서는 금액이라 관리자 계정만 보고 고칠 수 있습니다. 엑셀 백업에 견적, 견적 품목 시트가 들어갑니다.

1. **SQL 실행 (한 번만)**: SQL Editor → New query에 [`supabase/update-10.sql`](supabase/update-10.sql) 내용을 통째로 붙여넣고 Run. 맨 아래에 `시공자 정산 · 결산 · 견적서 표 준비 완료`가 보이면 끝입니다. 업데이트 8·9를 아직 안 했어도 이것 하나로 같이 됩니다.
2. **알림 서버 고치기 (한 번만)**: Supabase → Edge Functions → `notify` → **Code** 탭에서 내용을 모두 지우고 [`supabase/functions/notify/index.ts`](supabase/functions/notify/index.ts) 새 내용을 통째로 붙여넣은 뒤 **Deploy**. 고객용 견적서 링크가 열리게 됩니다(업데이트 9의 날짜별 시공자 알림도 같이 들어 있음).
3. 확인: **알림 서버 점검**에서 11·12·13번에 `[]`, 14번에 `404`와 `not found`, `"api":2`가 보이면 됩니다(14번이 `400 unknown action`이면 알림 서버 붙여넣기가 안 된 것).

**엑셀 양식으로 바꾼 뒤(2026-10-14)**: 업데이트 10을 이미 했다면 SQL은 다시 안 해도 됩니다. **알림 서버(notify) 코드만 한 번 더 붙여넣기** 하면 고객 링크에도 담당·소재·마감·하드웨어·단수 조정·브랜드 문구가 나옵니다. 안 하면 회사 기기에서 고객 화면을 열 때 위에 안내가 뜹니다(고객에게는 안 보임). 점검 14번에 `"api":2`가 보이면 된 것입니다.

## 엑셀 백업

현장 목록 맨 아래 **엑셀로 받기**를 누르면 지금까지의 기록이 엑셀 파일 하나(`NEST_backup_날짜.xlsx`)로 내려받아집니다. 아이폰에서는 공유 창이 열리니 "파일에 저장"을 고르면 됩니다.
시트: 현장, 마감 추가 투입, AS, 체크리스트, 사진·파일 목록, 시공자 명단. 관리자 계정은 수금, 입금 내역, 매입(자동 인건비 포함), 지출, 월별 결산, 시공자 일당, 시공자 정산, 견적, 견적 품목 시트도 함께 받습니다. 현장 시트에는 상태(대기중·진행중·종료)와 날짜별 시공자도 들어갑니다.
사진·도면·견적서 파일 자체는 엑셀에 들어가지 않고 목록만 들어갑니다. 무료 Supabase는 백업 파일을 따로 받을 수 없으니 한 달에 한 번쯤 받아 두세요(한 달이 넘으면 버튼 옆에 알림이 뜹니다).

## 보안 메모

anon 키는 공개되어도 되는 키입니다. 데이터는 로그인한 계정만 읽고 쓸 수 있도록 Supabase 행 수준 보안(RLS)으로 막혀 있습니다. 금액(수금·매입·지출·일당·정산·견적서)은 관리자 계정만 읽고 쓸 수 있습니다.
고객용 견적서 링크에도 견적서마다 다른 긴 열쇠가 들어 있어서, 그 링크를 가진 사람만 그 견적서 하나를 볼 수 있습니다(고치기는 안 됨). 견적서를 지우면 링크도 바로 막힙니다.
시공 체크리스트 링크에는 현장마다 다른 긴 열쇠가 들어 있어서, 그 링크를 가진 사람만 그 현장 체크리스트 하나를 쓸 수 있습니다. 시공자 화면에는 현관 비밀번호와 금액이 나오지 않고, 제출한 뒤에는 사무실에서 다시 열어 주기 전까지 고칠 수 없습니다. 링크가 새어 나갔다면 **링크 새로 만들기**를 누르면 예전 링크는 바로 막힙니다.
시방서 자동 찾기는 로그인한 계정만 시킬 수 있고, Anthropic에는 가전 모델명과 종류만 보냅니다(고객 이름·주소·일정·금액은 보내지 않음). Anthropic API 키는 Supabase Secrets에만 있고 앱 파일이나 GitHub에는 없습니다. 시공자 화면에는 보관함에서 찾은 자료만 붙고(공식 자료가 아니면 출처와 실측 안내가 함께 나옴), 보관함 PDF도 정해진 이름(`lib/spec/…pdf`)만 열 수 있게 막혀 있습니다. 서버가 이어서 찾거나 그림을 옮길 때 쓰는 내부 요청(`spec_step`, `spec_media`)은 서버 자신만 부를 수 있고, 그림 정리·PDF 캡처 요청은 로그인한 계정만 보낼 수 있습니다. Anthropic에는 모델명·종류와 시방서 그림만 보냅니다.

## 파일 보관 용량

Supabase 무료 요금제는 파일 합계 1GB, 파일 하나당 50MB까지입니다. 넘으면 Pro 요금제(월 25달러, 100GB)로 올리면 됩니다.
현장 사진은 올릴 때 자동으로 줄여서(장당 약 0.2~0.5MB) 저장합니다.
