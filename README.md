# 네스트퍼니처

현장별 실측일, 시공 기간과 시공자 배정, 마감 추가 투입 인원과 AS를 관리하고, 현장마다 사진·도면·견적서를 보관하는 웹앱입니다.
시공자별 일정판(겹침 경고), 수금 관리, 원가·매출 요약(관리자만), 휴대폰 알림(아침·저녁 일정)도 들어 있습니다.
PC와 휴대폰 브라우저에서 쓰고, 휴대폰 홈 화면에 설치하면 앱처럼 전체 화면으로 열립니다.

- 화면: `index.html`, `app.js` (빌드 과정 없음, 파일 그대로 올리면 됨)
- 저장·로그인·파일 보관: Supabase (`supabase/schema.sql` + `update-02.sql` + `update-03.sql`, 비공개 Storage 버킷 `job-files`)
- 알림 보내기: Supabase Edge Function `notify` (`supabase/functions/notify/index.ts`)
- 설치(PWA): `manifest.webmanifest`, `sw.js`, `icons/`

## 처음 설정

1. Supabase 프로젝트를 만들고 SQL Editor에서 `supabase/schema.sql`, 이어서 `supabase/update-02.sql` 내용을 실행합니다. 표(jobs, crew, files, admins, job_money)와 파일 보관함(job-files)이 만들어집니다.
2. Authentication → Sign In / Providers에서 "Allow new users to sign up"을 끕니다. (아무나 가입하지 못하게)
3. Authentication → Users → Add user로 사장님과 직원 계정(이메일, 비밀번호)을 만듭니다. "Auto Confirm User"를 체크하세요.
4. `config.js`에 Project URL과 anon public 키를 넣습니다. service_role 키는 넣지 않습니다.
5. GitHub 저장소 Settings → Pages에서 Source를 "Deploy from a branch", 브랜치 `main`, 폴더 `/ (root)`로 저장합니다.
   잠시 뒤 `https://<계정>.github.io/nest-schedule/` 주소로 열립니다.

## 업데이트 2 (현장 사진 · 수금 · 매출) 적용

이미 쓰고 있는 앱에는 Supabase → SQL Editor → New query에 `supabase/update-02.sql` 내용을 통째로 붙여넣고 Run을 한 번 누르면 됩니다.
처음 실행할 때 가장 먼저 만든 계정(사장님)이 관리자로 등록되고, 관리자만 계약금액·입금·원가·매출 화면을 볼 수 있습니다.

다른 계정도 관리자로 만들려면 SQL Editor에서 이메일만 바꿔 실행하세요.

```sql
insert into public.admins (user_id, email)
select id, email from auth.users where email = '직원이메일@example.com'
on conflict do nothing;
```

## 업데이트 3 (휴대폰 알림) 적용

매일 저녁 6시에 내일 일정, 아침 7시 30분에 오늘 일정과 시공자 미배정 현장을 휴대폰 알림으로 보냅니다. 관리자에게는 아침에 오늘 받을 돈과 입금 지연도 함께 갑니다.
앱을 닫아 둬도 옵니다. 알림을 누르면 앱이 열리면서 그날 일정(또는 수금 화면)이 바로 보입니다.

1. **알림 서버 만들기 (한 번만)**: Supabase → 왼쪽 **Edge Functions** → **Deploy a new function** → **Via Editor**.
   이름 칸에 정확히 `notify` 라고 적고, 편집기 내용을 지운 뒤 [`supabase/functions/notify/index.ts`](supabase/functions/notify/index.ts) 내용을 통째로 붙여넣고 **Deploy function**.
   비밀 키를 따로 넣을 필요는 없습니다(서버 안에 원래 들어 있는 값을 씁니다).
2. **SQL 실행 (한 번만)**: SQL Editor → New query에 `supabase/update-03.sql` 내용을 통째로 붙여넣고 Run.
   맨 아래에 `nest-push-morning`, `nest-push-evening` 두 줄이 보이면 끝입니다.
3. **기기마다 켜기**: 앱 오른쪽 위 **알림** → **이 기기에서 알림 켜기** → 허용 → **테스트 알림 보내기**.
   - 아이폰은 Safari에서 "홈 화면에 추가"한 앱으로 열어야 켤 수 있습니다(iOS 16.4 이상).
   - 기기마다 받을 알림(내일 일정 / 오늘 일정 / 입금)을 고를 수 있고, 로그아웃하면 그 기기 알림은 꺼집니다.

알림 시간을 바꾸려면 `update-03.sql`의 `30 22 * * *`(아침), `0 9 * * *`(저녁)을 고쳐 다시 실행하면 됩니다. 시간은 세계 표준시라 한국 시간에서 9시간을 빼서 적습니다. 아침 알림은 한국 시간 새벽 5시~낮 12시, 저녁 알림은 오후 3시~밤 11시 사이로만 정할 수 있습니다.

## 업데이트 4 (시공 체크리스트 · 가전 시방서) 적용

시공자가 시공을 마치고 휴대폰으로 체크리스트를 작성합니다. 가전마다 시방서 치수와 실제로 잰 치수, 시방서대로 설치했는지(통풍 간격, 도어 패널, 급배수, 전원 등)를 확인하고 사진을 남깁니다. 시공자는 로그인 없이 문자로 받은 링크로만 들어옵니다.

1. **SQL 실행 (한 번만)**: SQL Editor → New query에 `supabase/update-04.sql` 내용을 통째로 붙여넣고 Run. 맨 아래에 `체크리스트 준비 완료`가 보이면 끝입니다.
2. **알림 서버 고치기 (한 번만)**: Supabase → Edge Functions → `notify` → **Code** 탭에서 내용을 모두 지우고 [`supabase/functions/notify/index.ts`](supabase/functions/notify/index.ts) 새 내용을 통째로 붙여넣은 뒤 **Deploy**. 시공자 화면은 이 서버를 거쳐서만 저장됩니다.

쓰는 법
- 현장 수정 화면 **가전 · 시방서** 칸에 빌트인 가전 모델명만 적습니다. 업데이트 5를 하면 시방서는 모델명으로 자동으로 찾아 붙습니다. 공식 자료가 없는 가전은 **파일 직접 올리기**로 이 현장에만 올릴 수 있습니다.
- 같은 화면 **시공 체크리스트** 칸에서 **체크리스트 링크 만들기** → **체크리스트 문자 복사**해서 시공자에게 보냅니다. 달력에서 날짜를 눌러도 **체크리스트 문자 복사**가 있습니다.
- 시공자가 제출하면 알림이 오고(알림 설정의 "시공 체크리스트 제출"), 결과와 사진이 현장 화면에 보입니다. 문제로 적은 항목이 있으면 현장 목록에 빨갛게 표시되고, 고친 뒤 **문제 조치 완료**를 체크하면 사라집니다.
- 고칠 게 있어 다시 작성해야 하면 **다시 작성하게 열기**를 누르면 같은 링크로 다시 들어갈 수 있습니다.
- 시공이 끝났는데 체크리스트가 안 온 현장은 끝난 다음 날부터 7일 동안 아침 알림에 함께 나옵니다.
- 확인 항목 문구는 `checklist.js` 한 곳에서 고칩니다. 현장마다 따로 확인할 것은 **이 현장 추가 확인** 칸에 한 줄에 하나씩 적습니다.

## 업데이트 5 (시방서 자동 찾기) 적용

가전 모델명을 적고 저장하면, 알림 서버(`notify`)가 Claude(Anthropic의 AI)를 시켜 그 모델의 설치 시방서를 찾아 붙입니다. 제조사 공식 홈페이지를 먼저 찾고, 없으면 다른 출처에서 찾습니다(업데이트 6). 찾은 시방서는 모델별 보관함(`app_specs`)에 남아서, 같은 모델은 다음 현장부터 다시 찾지 않고 바로 붙습니다.

1. **Anthropic API 키 만들기 (한 번만)**: https://platform.claude.com 에 가입 → **Billing**에서 크레딧 충전(처음엔 5달러면 충분) → **API Keys** → **Create Key**. 키는 `sk-ant-`로 시작하고 만들 때 한 번만 보입니다. **Limits**에서 한 달 사용 한도(예: 20달러)를 정해 두면 그 이상은 쓰이지 않습니다.
2. **키 넣기 (한 번만)**: Supabase → **Edge Functions** → **Secrets** → 이름 `ANTHROPIC_API_KEY`, 값에 키를 붙여넣고 **Save**. 키는 여기에만 넣고 채팅·문자·앱 어디에도 보내지 마세요.
3. **SQL 실행 (한 번만)**: SQL Editor → New query에 [`supabase/update-05.sql`](supabase/update-05.sql) 내용을 통째로 붙여넣고 Run. 맨 아래에 `시방서 보관함 준비 완료`가 보이면 끝입니다.
4. **알림 서버 고치기 (한 번만)**: Supabase → Edge Functions → `notify` → **Code** 탭에서 내용을 모두 지우고 [`supabase/functions/notify/index.ts`](supabase/functions/notify/index.ts) 새 내용을 통째로 붙여넣은 뒤 **Deploy**.

쓰는 법
- 도면을 보고 **가전 · 시방서** 칸에 모델명만 적고 저장합니다. 몇 분 뒤 가전 줄 아래에 종류, 시공 때 맞춰야 할 치수, 치수도, 설명서·링크, 찾은 곳(출처)이 붙습니다. 앱을 닫아도 서버에서 계속 찾습니다. 저장하기 전에 **지금 찾기**를 눌러도 됩니다.
- 종류는 "종류 자동"으로 두면 찾은 시방서의 종류로 정해집니다.
- 어디에서도 못 찾으면 "어디에서도 찾지 못했어요"가 뜹니다. 모델명을 확인하고 **다시 찾기**를 누르세요. 그래도 없으면 **파일 직접 올리기**로 이 현장에만 올릴 수 있습니다.
- 어떤 현장만 치수가 다르면 "이 현장만 다른 치수" 칸에 적으면 그 현장에서는 그 값이 먼저 보입니다.
- 찾은 시방서는 같은 모델을 쓰는 모든 현장의 시공 체크리스트에 자동으로 붙습니다. PDF 설명서는 보관함에 복사해 두어서 제조사 주소가 바뀌어도 열립니다.

## 업데이트 6 (다른 출처 · 냉장고 붙여서 설치) 적용

- **공식 홈페이지에 없으면 다른 출처에서**: 제조사 공식 홈페이지(국내 → 해외)에 없으면 판매처 상품정보(롯데하이마트, 전자랜드, 다나와 등), 설명서 모음 사이트, 같은 시리즈 모델 순서로 찾습니다. 공식 자료가 아니면 앱과 시공자 화면에 **공식 자료 아님 · 출처: ○○**와 "현장에서 실측으로 꼭 확인해 주세요"가 함께 나옵니다.
- **더 끈질기게**: 한 번에 다 못 찾으면 서버가 이어서 몇 차례 더 찾습니다. 그래서 새 모델은 몇 분 걸릴 수 있습니다.
- **냉장고 붙여서 설치**: 한 현장에 냉장고·김치냉장고·와인셀러가 2대 이상이면 "옆 냉장고·김치냉장고와 붙여서 설치"가 기본으로 체크되고, 그 조합 그대로 설치할 때의 연결 시방서(묶음 전체 설치 공간, 제품 사이 간격·연결 키트, 통풍 간격)를 따로 찾습니다. 각 가전을 다 찾은 뒤에 자동으로 찾습니다. 시공 체크리스트에는 **붙여서 설치** 칸(5가지 확인 + 실측 + 사진)이 생깁니다. 따로 떨어져 설치하는 가전은 체크를 끄면 묶음에서 빠집니다.
- 예전 방식으로 못 찾았던 모델은 앱을 처음 열 때 새 방식으로 한 번 다시 찾습니다.

1. **SQL 실행 (한 번만)**: SQL Editor → New query에 [`supabase/update-06.sql`](supabase/update-06.sql) 내용을 통째로 붙여넣고 Run. 맨 아래에 `시방서 출처 칸 준비 완료`가 보이면 끝입니다.
2. **알림 서버 고치기 (한 번만)**: Supabase → Edge Functions → `notify` → **Code** 탭에서 내용을 모두 지우고 [`supabase/functions/notify/index.ts`](supabase/functions/notify/index.ts) 새 내용을 통째로 붙여넣은 뒤 **Deploy**.
3. 확인은 GitHub **Actions** → **알림 서버 점검** → **Run workflow**. 7번에 `"v":2`, 8번에 `[]`, 9번에 `403`이 보이면 됩니다.

비용
- 새 모델 하나를 찾을 때 보통 몇백 원에서 2천 원 정도 듭니다(Claude 사용료와 웹 검색 몇 번, 모델마다 다름). 공식 홈페이지에 없어 여러 차례 찾는 모델이나 붙여서 설치 묶음은 몇천 원, 드물게 1만 원 가까이 들 수 있습니다. 같은 모델·같은 묶음은 다시 찾지 않아서 0원입니다.
- 실수로 많이 찾지 않도록 24시간에 30개까지만 찾습니다. 바꾸려면 Secrets에 `SPEC_DAY_CAP`(숫자)을 넣습니다.
- 키를 넣지 않으면 자동 찾기만 꺼지고 앱의 나머지는 그대로 동작합니다.
- 크레딧이 떨어지면 가전 줄 아래에 "Claude API 크레딧이 모자라요"가 뜹니다. Claude Console(platform.claude.com) → Billing에서 충전하고 **다시 찾기**를 누르세요.

## 엑셀 백업

현장 목록 맨 아래 **엑셀로 받기**를 누르면 지금까지의 기록이 엑셀 파일 하나(`NEST_backup_날짜.xlsx`)로 내려받아집니다. 아이폰에서는 공유 창이 열리니 "파일에 저장"을 고르면 됩니다.
시트: 현장, 마감 추가 투입, AS, 체크리스트, 사진·파일 목록, 시공자 명단. 관리자 계정은 수금, 입금 내역, 원가 시트도 함께 받습니다.
사진·도면·견적서 파일 자체는 엑셀에 들어가지 않고 목록만 들어갑니다. 무료 Supabase는 백업 파일을 따로 받을 수 없으니 한 달에 한 번쯤 받아 두세요(한 달이 넘으면 버튼 옆에 알림이 뜹니다).

## 보안 메모

anon 키는 공개되어도 되는 키입니다. 데이터는 로그인한 계정만 읽고 쓸 수 있도록 Supabase 행 수준 보안(RLS)으로 막혀 있습니다.
시공 체크리스트 링크에는 현장마다 다른 긴 열쇠가 들어 있어서, 그 링크를 가진 사람만 그 현장 체크리스트 하나를 쓸 수 있습니다. 시공자 화면에는 현관 비밀번호와 금액이 나오지 않고, 제출한 뒤에는 사무실에서 다시 열어 주기 전까지 고칠 수 없습니다. 링크가 새어 나갔다면 **링크 새로 만들기**를 누르면 예전 링크는 바로 막힙니다.
시방서 자동 찾기는 로그인한 계정만 시킬 수 있고, Anthropic에는 가전 모델명과 종류만 보냅니다(고객 이름·주소·일정·금액은 보내지 않음). Anthropic API 키는 Supabase Secrets에만 있고 앱 파일이나 GitHub에는 없습니다. 시공자 화면에는 보관함에서 찾은 자료만 붙고(공식 자료가 아니면 출처와 실측 안내가 함께 나옴), 보관함 PDF도 정해진 이름(`lib/spec/…pdf`)만 열 수 있게 막혀 있습니다. 서버가 이어서 찾을 때 쓰는 내부 요청(`spec_step`)은 서버 자신만 부를 수 있습니다.

## 파일 보관 용량

Supabase 무료 요금제는 파일 합계 1GB, 파일 하나당 50MB까지입니다. 넘으면 Pro 요금제(월 25달러, 100GB)로 올리면 됩니다.
현장 사진은 올릴 때 자동으로 줄여서(장당 약 0.2~0.5MB) 저장합니다.
